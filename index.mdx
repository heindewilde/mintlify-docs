## Free plan and paid plans

Every account can use the API, the CLI and the MCP server. What a workspace can reach depends on its plan.

| | Free | Leaf | Tree |
| --- | --- | --- | --- |
| Price | €0 | {leafPrice} a month | {treePrice} a month |
| Transfers and contacts | Yes | Yes | Yes |
| Webhooks | 1 endpoint, transfer events | 10 endpoints, all events | 10 endpoints, all events |
| Largest transfer | {freeTransfer} | {leafQuota} | {treeQuota} |
| Transfer lifetime | {freeDays} days | You choose | You choose |
| Collections and upload requests | No | Yes, {leafQuota} of storage | Yes, {treeQuota} of storage |

Uploads made through the API are metered apart from the plans, the same way on every tier: the first {apiFreeUsage} each month are free, then {apiPricePerGb} per GB from prepaid credit. Downloads are never metered. [Pricing](https://yungle.co/pricing) has the full plan details.

## The base URL

Every endpoint lives under one base URL, takes JSON and returns JSON:

```text
https://yungle.co/api/v1
```

You authenticate with an API key sent as a bearer token. [Authentication](/authentication) covers keys and scopes. The full list of endpoints is in the [API reference](/api-reference), generated from the [OpenAPI 3.1 document](https://yungle.co/api/v1/openapi.json).

`/api/v1` changes only by adding things. New endpoints and new response fields can appear; existing fields keep their meaning, and no new required request field is added. A breaking change would get `/api/v2`, and v1 would keep working.

The CLI, the MCP server and the JavaScript and Python SDKs are open source (MIT) on [GitHub](https://github.com/heindewilde/yungle-clients).

## What you get

Yungle is small, independent and self-hosted in the EU. Your files are always encrypted, nothing is sent to a US cloud, and every byte is served from the EU under a data processing agreement.

Free usage is free: {apiFreeUsage} of API uploads each month, {apiFreeCalls} calls, and {freeTransfer} per transfer, with no card and no trial clock. Beyond the upload allowance, you pay {apiPricePerGb} per GB from credit you top up in advance.

Credit is prepaid on purpose. No invoice can arrive for traffic you did not expect, and a runaway script cannot spend money you have not put in. When the balance runs out, your next upload is refused before any bytes move, so the failure lands on you, where you can see it, and never on a recipient waiting for a file. The call allowance is an abuse guard rather than a price, set far above what a working integration uses.

<Note>
The vault and end-to-end encrypted transfers are encrypted in the client with keys Yungle never receives, so the API can never read them. [What the API cannot do](/unsupported) explains where that boundary is.
</Note>
