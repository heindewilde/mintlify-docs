### `yungle login`

Opens your browser to sign in; nothing to copy, and it works over SSH because the browser can be on another machine. The session refreshes itself, including during long uploads. On a server or in CI, save an API key with --key instead, or set YUNGLE_API_KEY, which is always read first.

| Flag | What it does |
| --- | --- |
| `--key <key>` | use an API key instead (servers, CI); asks if left out |
| `--no-browser` | print the link instead of opening it |

### `yungle whoami`

The workspace, plan, storage used, and how you are signed in (browser, saved key, or YUNGLE_API_KEY).

### `yungle logout`

Revokes the browser session on the server and forgets it on this machine.

### `yungle send <paths…>`

Uploads resumably: interrupt it and run the same command again, and it carries on from the last committed part. Folders keep their structure; hidden files are skipped. Without --to you get a link and nobody is emailed; --to needs an API key (yungle login --key), because a browser sign-in never emails anyone. Run it with no paths at a terminal and it asks what to send.

| Flag | What it does |
| --- | --- |
| `--from-url <url>` | also send a file Yungle fetches from a URL (repeatable) |
| `--to <email>` | recipient (repeatable, or comma-separated) |
| `--message <text>` | note for the recipients |
| `--title <text>` | label for your dashboard |
| `--password <text>` | recipients must enter this |
| `--expires <days>` | lifetime, clamped to your plan |

### `yungle get <link>`

Needs no account: the link is the credential. Asks for the password if the transfer has one, and resumes an interrupted download. End-to-end encrypted transfers open only in a browser.

| Flag | What it does |
| --- | --- |
| `--out <dir>` | where to save (default: current directory) |
| `--zip` | one zip instead of separate files |
| `--password <text>` | for a protected link; asks if left out |

### `yungle put <file> --target <target>`

For AI assistants that cannot reach your disk: the assistant prepares the upload and hands you one command with a target in it. Running it checks the file is the one the target was made for, then uploads it resumably, renewing its token as it goes.

### `yungle status [<id\|link>]`

Per recipient: emailed, downloaded, or bounced, plus the link and when it expires. Takes the full id, the short id from yungle transfers, or the link; with none, it lets you pick from your recent transfers.

### `yungle transfers`

The latest 25, with size, downloads and time left.

### `yungle revoke <id>`

Destroys the files and ends the link immediately. Asks first at a terminal; cannot be undone.

### `yungle push <paths…> --collection <id>`

Resumable like send. Folder structure is kept.

| Flag | What it does |
| --- | --- |
| `--folder <id>` | target folder |
| `--from-url <url>` | also add a file Yungle fetches from a URL (repeatable) |

### `yungle watch <dir> --collection <id>`

For render farms, card readers and export folders. A file goes up once it has stopped changing, what went up is remembered across restarts, and files already in the folder are left alone unless --existing.

| Flag | What it does |
| --- | --- |
| `--interval <seconds>` | how often to look (default 10) |
| `--existing` | also upload what is already in the folder |

### `yungle pull --collection <id>`

Downloads a whole collection into a folder, keeping its folder structure, resumably: run it again and it skips what is already there at full size. With --transfer it downloads one of your own transfers instead.

| Flag | What it does |
| --- | --- |
| `--transfer <id>` | download your own transfer instead |
| `--out <dir>` | where to save (default: the collection's title) |
| `--zip` | one zip instead of separate files |

### `yungle requests pause\|resume\|close <id>`

Pause and close both stop new uploads through the link; resume opens it again.

### `yungle webhooks listen`

Reads a pull endpoint of its own, so it needs no public URL, and prints each event live. With --forward-to it also POSTs each one, signed with the session's secret, to a server on your machine while you build the receiver.

| Flag | What it does |
| --- | --- |
| `--forward-to <url>` | also POST each one, signed, to a local server |

### `yungle mcp install`

Writes the local MCP server into your assistant's config, with a saved API key (a browser sign-in expires too soon to live in a config file). Refuses keys with more power than the server uses; transfers:write needs --allow-write. Simpler still: add https://yungle.co/mcp to your assistant and sign in there.

| Flag | What it does |
| --- | --- |
| `--client <id>` | claude-desktop \| claude-code \| cursor \| windsurf |
| `--dry-run` | show what would change, write nothing |
| `--allow-write` | accept a key with transfers:write (share links) |

### `yungle mcp status`

Show where it is installed.
