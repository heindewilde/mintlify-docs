---
title: "Agent hand-off over MCP"
description: "Connect Claude, Cursor or any MCP client to Yungle with no key: ask about your transfers, share files as links, and keep every email behind your yes."
---

Most of the questions you ask about sent files are lookups: did the client download it, what
is in that collection, what did I send to Anna last week. An AI assistant connected to
Yungle answers them in a sentence. This recipe sets that up, and is precise about where the
assistant stops and you take over.

## 1. Connect it

In your assistant, add `https://yungle.co/mcp` as a remote MCP server (a custom
connector in Claude; the `url` field in Cursor, VS Code and Windsurf). It opens Yungle,
you sign in, and you choose what it may do. Leave “Email recipients” unticked
unless you want it to be able to send, and even then it asks you every time.

```json
{ "mcpServers": { "yungle": { "url": "https://yungle.co/mcp" } } }
```

## 2. Or run it on your machine

The local server can also share files and folders straight from your disk, and save a
link’s files into a folder you name (`download_files`). It needs an API key; give it
only the `:read` scopes, plus `transfers:write` if it should share links.

```bash
npm install -g yungle-cli
yungle login --key                         # paste the key (the local server needs one)
yungle mcp install --client claude-desktop --dry-run   # see the change
yungle mcp install --client claude-desktop            # add --allow-write for transfers:write
yungle mcp status
```

`--client` also takes `claude-code`, `cursor` and `windsurf`. Restart
the assistant so it picks up the new server.

## 3. Ask it things

| You ask | It uses |
| --- | --- |
| “Has De Vries downloaded the Q3 report yet?” | `list_transfers, get_transfer_downloads` |
| “What is still sitting in the Harbour collection?” | `list_collections, list_collection_files` |
| “Who have I invited to the wedding gallery?” | `list_guests` |
| “How much storage do I have left?” | `get_account` |
| “What is Anna’s email address?” | `list_contacts` |
| “Put these meeting notes on a link for me.” | `create_share_link` |
| “Send the client the render in our S3 bucket.” (a presigned link, any size) | `share_from_urls, get_import_status` |
| “What is in the link Anna sent me?” | `get_download_links` |
| “Has anyone used the upload link for the Harbour shoot?” | `list_upload_requests, get_upload_request` |
| “Send the link to Anna.” (if you allowed email) | `send_transfer, after you confirm` |

**Big files.** A chat has no way to carry a 40 GB file,
so the assistant does not try. `share_from_urls` hands Yungle a URL where the file
already is and Yungle fetches it itself. `create_transfer` gives an assistant that has
a shell (Claude Code, Cursor’s agent) one `npx yungle-cli put …` command per
file. Each command needs no key, can upload only that one file, and resumes if the
connection drops.

Download receipts count one visit as one download, even when the recipient saved eight
files. The tool’s description tells the model to count distinct sessions, so “how
many times” comes back right.

## 4. Where it hands back to you

- **Emailing.** It shares links and hands them to you. It can email one only if you ticked “Email recipients”, and then your client asks you first, every time, with the addresses and the note in front of you. A client that cannot ask gets the link back instead.
- **Deleting, revoking, inviting.** No tool exists for any of them, so a misread instruction cannot take a link away from a client. Nor can it open an upload request: a public upload page lets strangers into your storage, so the assistant can list them but not create them.
- **Contents.** The server returns names, sizes, receipts and, when asked for them, download links. It never puts a file’s contents into the conversation. An assistant that can fetch URLs can follow those links, just as you could. The vault is not visible at all.

<Note>
  Filenames and messages come from other people. The server labels them as untrusted data,
  so a file called “ignore previous instructions” is reported, not obeyed.
</Note>

Every tool, with its inputs, is in the [MCP reference](/mcp).
